# 先生方向け利用ガイド（vLLM Manager / 学内 AI 基盤）

このドキュメントは、学内に構築した AI（大規模言語モデル）基盤「vLLM Manager」を、教職員の皆さまに使っていただくための案内です。管理者（情報担当）が配布することを想定しています。

- 対象読者: 授業・研究・校務で AI を使ってみたい先生方
- 前提知識: パソコンでのソフト設定（アプリのインストール、設定画面への入力）程度ができれば十分です。プログラミングの知識は必須ではありません
- サポート窓口: 本ガイド末尾の「困ったときは」を参照してください

---

## 1. これは何のシステムですか？

`vLLM Manager` は、学内サーバー上で動く AI（ChatGPT のような大規模言語モデル）を、学内の先生方が共通で使えるようにするための基盤です。

- **どこにあるデータも外部（学外のクラウド）には送られません**。すべて学内サーバー上で処理されます（機密性の高い教材・学生の個人情報を含む文章を扱う際も、外部 SaaS 版の生成 AI より安心して使える構成です）。
- 使い方は大きく2通りあります。

| 使い方 | 向いている人 |
|--------|--------------|
| ① 管理画面のチャットタブで AI と会話する | まずは試してみたい、手軽に会話したい方（**おすすめ**） |
| ② チャットアプリ（例: Chatbox）で AI と会話する | デスクトップアプリで使いたい、高度な設定をしたい方 |
| ③ API を直接呼び出して、自作のツールやスクリプトから利用する | Excel マクロや自作プログラムに AI 機能を組み込みたい方 |

どちらの使い方でも、最初に **アカウントと API キーの発行** が必要です。

---

## 2. 使い始めるまでの流れ（全体像）

```text
① 管理者にアカウント発行を依頼
        │
        ▼
② 管理画面にログインし、自分の API キーを確認
        │
        ▼
③-a 管理画面の「チャット」タブで会話（API キー不要・おすすめ）    または
③-b チャットアプリ（例: Chatbox）に API キーを設定して会話    または
③-c API を直接呼び出して自作ツール・スクリプトから利用
```

---

## 3. アカウント・API キーを受け取る

vLLM Manager の利用には、管理者が発行する次の2つの情報が必要です。管理者からこれらを受け取ってください（本ガイドと一緒に配布されている場合もあります）。

| 項目 | 用途 |
|------|------|
| ログイン ID・パスワード | 管理画面（Web ブラウザ）にログインするため |
| API キー（`sk-` から始まる文字列） | チャットアプリや自作プログラムから AI を呼び出すため |

> 一般ユーザー（先生方のアカウント）は、管理画面から自分で API キーを新規発行することはできません。追加のキーが必要な場合や、利用できるモデルを増やしたい場合は管理者にご依頼ください。

---

## 4. 管理画面にログインする

1. ブラウザで次の URL を開きます。

   ```text
   http://hinton.kanazawa-it.ac.jp:13000
   ```

2. 受け取ったログイン ID・パスワードを入力し、「ログイン」を押します。
3. ログインすると次のタブが表示されます（一般ユーザーの場合）。

| タブ | 内容 |
|------|------|
| ホーム | サーバー（GPU）の稼働状況を確認できます |
| **チャット** | **ログイン後すぐ AI と会話できます（API キーの設定不要）** |
| モニタリング | AI へのリクエスト状況（同時実行数など）を確認できます |
| マイページ | ご自身のパスワード変更、発行済み API キーの確認ができます |

4. **まず試すなら「チャット」タブ**を開いてください。起動中のモデルを選び、メッセージを入力して送信するだけで会話を始められます。外部アプリ（Chatbox 等）のインストールは不要です。

5. 外部アプリや自作プログラムから使う場合は、「マイページ」タブで発行済みの API キーを確認します。「APIキーをコピー」でクリップボードにコピーできます。これを後述の手順で使います。

---

## 5. 管理画面のチャットタブで会話する（おすすめ）

1. ログイン後、画面上部の **「チャット」** タブをクリックします。
2. 「モデル」ドロップダウンから利用したいモデルを選びます（起動中のモデルのみ表示されます）。
3. 下部の入力欄にメッセージを入力し、「送信」を押します。
   - **Enter** で送信、**Shift+Enter** で改行できます。
4. AI の応答はリアルタイムで表示されます。「新しい会話」で履歴をクリアできます。

> 会話履歴はお使いのブラウザにのみ保存されます（サーバーには残りません）。管理者は運用上、リクエスト履歴から推論ログを確認できる場合があります。

---

## 6. 接続先の情報（Chatbox / API 利用時・重要）

チャットアプリの設定や、API を直接呼び出すプログラムを書く際は、次の情報を使います。**ツールによって呼び方が違う**ので、下表で読み替えてください。

| 設定画面での呼び方の例 | 入力する値 |
|------------------------|------------|
| Base URL / API Base / エンドポイント URL / API Endpoint | `http://hinton.kanazawa-it.ac.jp:14000/v1` |
| API Key / API キー / Access Token | 管理者から配布された `sk-` から始まる API キー |
| Model / モデル名 | `vllm-local`、または実際のモデル ID（詳細は 6-3 を参照） |

> `14000` は「LiteLLM」という中継サーバーのポート番号です。個人の API キーごとの利用状況・利用制限もここで管理されているため、通常はこの `14000` 番を使ってください。

> **重要**: モデル名に何を入れるべきかは「サーバー上でモデルが何個同時に動いているか」によって変わります。必ず 6-3 を読んでから設定してください。

## 7. すぐに試す：チャットアプリで会話する

もっとも手軽な確認方法として、無料のデスクトップ用チャットアプリ「Chatbox」を使う例を紹介します（他の OpenAI 互換チャットアプリでも同様の手順で使えます）。

### 6-1. Chatbox のインストール

公式サイト（<https://chatboxai.app/>）から Windows / Mac 版をダウンロードし、インストールします。

### 6-2. 接続設定

1. Chatbox を起動し、設定（歯車アイコン）を開きます。
2. モデルプロバイダーの追加、または「カスタムプロバイダー」を選びます。
3. 次の内容を入力します。

   | 項目 | 値 |
   |------|-----|
   | API モード | OpenAI API 互換 |
   | API ドメイン / Base URL | `http://hinton.kanazawa-it.ac.jp:14000/v1` |
   | API キー | 配布された `sk-` から始まるキー |
   | モデル名 | `vllm-local`（複数モデルが同時稼働している場合は 6-3 を参照） |

4. 保存すると、通常のチャット画面と同じ感覚で AI と会話できます。

### 6-3. モデル名について（重要）

**「今サーバー上で会話用（chat）モデルが1つだけ動いているか、複数同時に動いているか」で指定すべきモデル名が変わります。**

| サーバーの状態 | モデル名に指定する値 |
|----------------|----------------------|
| 会話用モデルが **1つだけ** 動いている（一番よくある構成） | `vllm-local` でそのモデルに接続できます |
| 会話用モデルが **複数同時に** 動いている（例: 通常会話用モデルとエージェント用モデルを同時起動している場合など） | `vllm-local` を指定すると、どれか1つ（管理者が優先設定したもの、または一番若い番号のモデル）に固定でつながります。**狙ったモデルを使いたい場合は、そのモデルの正式な ID を直接指定する必要があります** |

複数モデルが動いていて、使いたいモデルの ID が分からない場合は、次のいずれかで確認してください。

- 管理者に「今使えるモデルの一覧」を確認する
- 自分で確認したい場合は、7-4 の方法（`GET /v1/models`）で一覧を取得する

正式な ID は `Qwen/Qwen2.5-7B-Instruct` のように「作成元/モデル名」の形式になっていることが多いです。この文字列を、Chatbox やその他のツールの「モデル名」欄に **そのままコピー** して入力してください（`vllm-local` の代わりに使います）。

> 迷ったときは、まず `vllm-local` で試してみて、想定と違うモデルの応答（口調・得意分野が違う等）が返ってきた場合に、正式なモデル ID を指定する方法に切り替えるとよいです。

## 8. API を直接使う（リクエスト例）

Excel マクロや Python スクリプトなど、自分で作ったプログラムから AI を呼び出したい場合は、この章の「API リクエスト」を使います。チャットアプリだけを使う方は読み飛ばしていただいて構いません。

用語の整理:

| 用語 | 意味 |
|------|------|
| API | プログラムから AI に「質問を送って回答をもらう」ための窓口 |
| エンドポイント | API の宛先 URL |
| リクエスト | プログラムから送る「質問」のデータ |
| レスポンス | AI から返ってくる「回答」のデータ（JSON 形式） |

### 7-1. 動作確認（コマンドラインから）

Mac や Windows の「ターミナル」「PowerShell」「Git Bash」などで、次のコマンドを実行すると、コマンドラインからでも AI の応答を確認できます（`curl` というコマンドを使います。Mac には標準で入っています。Windows 10/11 の PowerShell にも標準で入っています）。

`<APIキー>` の部分だけ、配布された自分の API キーに書き換えてください。

```bash
curl "http://hinton.kanazawa-it.ac.jp:14000/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <APIキー>" \
  -d '{
    "model": "vllm-local",
    "messages": [
      {"role": "user", "content": "こんにちは。あなたは何ができますか？"}
    ],
    "max_tokens": 256
  }'
```

**リクエストの中身の意味**

| 項目 | 意味 |
|------|------|
| `Authorization: Bearer <APIキー>` | 本人確認用の情報です。ここに API キーを入れます |
| `model` | 使う AI モデルの名前。会話用モデルが1つだけ動いている場合は `vllm-local` で問題ありません。複数同時に動いている場合は、狙ったモデルの正式な ID を指定する必要があります（詳しくは 6-3、確認方法は 7-4 を参照） |
| `messages` | 会話の内容。`role: "user"` が自分（利用者）の発言です |
| `max_tokens` | AI に返してほしい回答の最大の長さ（目安: 日本語 1〜2 文字 ≒ 1〜2 トークン） |

うまくいくと、次のような JSON（データの形式）が返ってきます。

```json
{
  "id": "chatcmpl-xxxxxxxx",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "こんにちは！文章の作成や要約、質問への回答などをお手伝いできます。"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 18,
    "completion_tokens": 32,
    "total_tokens": 50
  }
}
```

- AI の回答本文は `choices[0].message.content` に入っています。
- `usage` には、今回のやり取りで使ったトークン数（≒文章量）が表示されます。

### 7-2. 会話を続ける（やり取りの履歴を送る）

AI との「会話」を続けたい場合は、`messages` にこれまでのやり取りを順番に並べて送ります（AI 側はリクエストのたびに全履歴を受け取って回答しています）。

```json
{
  "model": "vllm-local",
  "messages": [
    {"role": "user", "content": "日本の四季を1つずつ簡単に説明してください。"},
    {"role": "assistant", "content": "春は桜が咲き、気候が穏やかになる季節です。..."},
    {"role": "user", "content": "では夏についてもう少し詳しく教えてください。"}
  ],
  "max_tokens": 256
}
```

### 7-3. Python から呼び出す例

プログラミングで組み込みたい場合は、Python の `requests` ライブラリを使うと簡潔に書けます（事前に `pip install requests` が必要です）。

```python
import requests

API_BASE = "http://hinton.kanazawa-it.ac.jp:14000/v1"
API_KEY = "配布されたAPIキーをここに入れる"

response = requests.post(
    f"{API_BASE}/chat/completions",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={
        "model": "vllm-local",
        "messages": [
            {"role": "user", "content": "この文章を100文字程度で要約してください: ..."}
        ],
        "max_tokens": 256,
    },
    timeout=120,
)
response.raise_for_status()
data = response.json()
print(data["choices"][0]["message"]["content"])
```

### 7-4. 今どんなモデルが使えるか確認する（複数モデル稼働時は必読）

次のコマンドで、現在サーバー上で起動している AI モデルの一覧を確認できます。

```bash
curl "http://hinton.kanazawa-it.ac.jp:14000/v1/models" \
  -H "Authorization: Bearer <APIキー>"
```

返ってくる JSON は次のような形です。`data` の中に、今動いているモデルが1件ずつ並びます。

```json
{
  "object": "list",
  "data": [
    { "id": "Qwen/Qwen2.5-7B-Instruct", "object": "model" },
    { "id": "meta-llama/Llama-3.1-8B-Instruct", "object": "model" }
  ]
}
```

- 表示された `id` の値（例: `Qwen/Qwen2.5-7B-Instruct`）を、そのまま 7-1 や 7-2 のリクエストの `"model"` の値としてコピー＆ペーストして使ってください。
- `data` に **1件しか表示されない場合**は、`vllm-local` を指定してもその1件に必ずつながるので、`vllm-local` のままで問題ありません。
- `data` に **複数件表示される場合**は、`vllm-local` だとどれか1つに固定でつながってしまうため、**使いたいモデルの `id` を直接指定してください**。

### 7-5. Excel（VBA）から使う場合のヒント

Excel マクロ（VBA）からも `MSXML2.XMLHTTP` 等の HTTP リクエスト機能を使って同様に呼び出せます。送信する内容は 7-1 の JSON と同じです。VBA での実装が難しい場合は、7-3 の Python スクリプトを Excel から `Shell` 関数で呼び出す方法もあります。詳しい実装支援が必要な場合は管理者にご相談ください。

## 9. よくある質問（FAQ）

**Q. AI に送った内容は外部に漏れませんか？**
A. すべて学内サーバー内で処理され、外部の AI サービス（OpenAI 社等）には送信されません。

**Q. 使えるモデルは変更できますか？**
A. 起動するモデルの切り替えは管理者のみが行えます。特定のモデルを使いたい場合はご相談ください。

**Q. 応答が遅い・エラーが出ます**
A. 他の利用者と GPU を共有しているため、同時に多くの利用があると遅くなることがあります。しばらく待っても改善しない場合は「9. 困ったときは」を確認のうえ管理者にご連絡ください。

**Q. API キーを他の人と共有してよいですか？**
A. 共有しないでください。API キーは個人ごとの利用量管理・アクセス制御の単位です。複数名で使いたい場合は管理者にチーム利用の設定を依頼してください。

**Q. 自分で新しい API キーを発行したい**
A. 一般ユーザーは自分で発行できません。管理者にご依頼ください。

## 10. 困ったときは

以下を確認しても解決しない場合は、管理者までご連絡ください。連絡の際は、下記もあわせてお伝えいただけるとスムーズです。

- 使用したツール名（例: Chatbox / curl / Python スクリプト / Excel マクロ）
- 発生した時刻
- 表示されたエラーメッセージ（あれば画面のスクリーンショット）

| 症状 | 確認すること |
|------|--------------|
| ログインできない | ログイン ID・パスワードが正しいか。分からない場合は管理者に再確認 |
| チャットアプリ側で「接続できません」と出る | Base URL・API キーの入力ミスがないか（コピー時の余分な空白等） |
| 応答がずっと返ってこない | 内容が非常に長い、または一度に多くの人が利用している可能性。時間をおいて再試行 |
| 「401」「403」などのエラー | API キーが正しいか、有効期限が切れていないか。管理者に確認 |
